# M1.5 results — launcher shell + CI APK

## Why CI builds the APK
Stock `aapt2` (build-tools 35.0.0) is an x86-64 ELF — `Exec format`-class
failure on this ARM64 phone (same finding as the NDK toolchain). Verified by
`file` inspection, not worked around with random ARM binaries. Phone builds
`.so` + `.levipack`; CI assembles the APK.

## Native (unchanged, re-verified this session)
- Clean rebuild: `libxykell.so` 127,448 bytes, ARM aarch64, `T PLGetModRegistration`.
- Preloader call sites confirmed external: `registerTouchCallback`,
  `registerModule`, `unregisterModule`, `submitDrawCommands`.
- `native/` untouched by the launcher work (only manifest gained the documented
  `overwrite_*` fields in M1).

## Launcher shell (new, `app/`, uncompiled until CI runs)
- 6 screens: Home (real device diag via `Build`, disabled PLAY + NOT WIRED),
  Versions / Modules / Profiles (Default) / Settings / About (real version strings).
- Zero external deps beyond `appcompat`; Kotlin + classic Views.
- Runtime managers return honest NOT WIRED states; no invented intents/APIs.
